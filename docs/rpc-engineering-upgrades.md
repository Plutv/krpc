# KRPC 工程化升级说明

本文记录本轮改造的问题来源、设计选择、收益和验证边界，可作为项目复盘及面试讲解提纲。

## 1. 客户端请求生命周期与背压

### 问题

- 单 Channel 并发复用时，仅使用 `requestId -> Future` 保存请求。连接突然断开后，在途请求不知道自己属于哪个 Channel，只能等待统一超时。
- Netty 出站缓冲持续增长时，客户端仍会继续写入，突发流量可能转化为直接内存压力。

### 设计

- 在途请求同时记录 `requestId`、Future 和 ChannelId。
- `channelInactive` 时按 Channel 批量异常完成 Future，写失败和调用结束时均执行幂等删除。
- 配置 Netty 写缓冲高低水位；Channel 不可写时快速返回过载错误。
- Channel 关闭后同时清理连接缓存及该地址的建连锁，避免节点数量长期增长造成锁缓存泄漏。

### 收益与取舍

- 故障连接上的请求立即被唤醒，失败耗时不再被固定超时上限放大。
- 请求表通过条件删除处理“响应、超时、断连”之间的竞争，不会重复完成 Future。
- 快速失败保护客户端内存，但高低水位过小会降低吞吐，需要通过压测按报文大小调整。

## 2. EventLoop 隔离与服务端过载保护

### 问题

- 原实现直接在 Netty EventLoop 中反射调用业务方法。一个慢调用会阻塞同一 EventLoop 管理的其他连接，造成延迟扩散。
- 使用无界任务队列只能把过载转移为内存堆积，不能形成稳定的容量边界。

### 设计

- EventLoop 只负责协议编解码和任务投递，业务调用进入服务端共享的固定大小线程池。
- 使用有界队列和拒绝策略；线程与队列均满时返回 `503 server overloaded`。
- 服务停止时先停止接收请求并排空业务任务，再关闭 I/O 线程和注册中心资源。
- 暴露活跃线程数和队列长度，用于拒绝日志及后续指标采集。

### 收益与取舍

- 慢业务不会长期占用 I/O 线程，故障影响范围从 EventLoop 收敛到业务线程池。
- 有界队列提供明确的最大排队量，可用少量拒绝换取进程稳定。
- 线程数、队列容量和拒绝比例不存在通用最优值，需要结合服务时间、CPU 利用率和 P99 调参。

## 3. ZooKeeper 状态收敛与注册语义

### 问题

- 单次超时立即摘除节点会把网络抖动误判为实例故障。
- Watcher 只处理增量事件；客户端与 ZooKeeper 断开期间可能丢失状态变化。
- 原“可重试”标记为 `/CanRetry/{service}` 单个临时节点。多 Provider 部署时，一个实例注销会误删整个服务的重试标记。
- 手工创建的临时节点在 ZooKeeper 会话丢失后不会自动重建；正常停机若不关闭注册客户端，消费者也要等待会话过期。

### 设计

- 节点连续失败达到阈值后才隔离，任意一次成功响应清零失败计数；隔离节点由定时 TCP 探测恢复。
- Watcher 负责实时增量更新，`RECONNECTED` 后从注册中心全量拉取并与本地缓存、负载均衡器对账。
- 重试元数据改为 `/CanRetry/{service}/{address}`，每个 Provider 只管理自己的临时子节点；只有当前所有服务节点都声明可重试时，消费者才允许重试。
- Provider 使用 Curator `PersistentNode` 管理临时节点，使其在会话恢复后自动重建；服务端关闭时主动注销并关闭 ZooKeeper 客户端。

### 收益与取舍

- 降低瞬时抖动造成的误摘除，同时仍能在连续故障后隔离节点。
- 增量 Watcher 保证实时性，全量对账保证最终一致性，职责互补。
- Provider 级重试元数据修复多实例互相覆盖的问题，并保守规避非幂等节点被重试。
- 连续失败阈值会增加真实故障的发现时间，应结合连接失败、超时率和探测周期共同调整。

## 4. 配置与链路上下文

- 为 Lombok Builder 字段补充 `@Builder.Default`，避免部分构建配置时未显式字段变为 `null`。
- 将注册中心地址、会话超时、失败阈值、探测周期、业务线程数和队列容量配置化。
- 解码器不再修改 EventLoop 的 MDC，而是将协议 Trace 信息写回请求对象；业务线程显式建立并在 `finally` 中清理上下文。
- SpanId 改为并发安全的 Snowflake 序列，避免同一毫秒内多个请求产生相同 SpanId。

## 5. 自动化验证

- 协议：半包、粘包等价的分段输入、非法魔数、超长帧、请求响应往返。
- 请求关联：乱序响应、并发响应、写失败、迟到响应、Channel 关闭批量失败及零残留。
- 过载保护：单工作线程和单队列槽位占满后，后续任务被确定性拒绝。
- 节点健康：连续失败达到阈值才隔离，成功会重置失败序列。
- 集成调用：单 Channel、64 并发、2000 次调用全部成功，完成后在途请求数为 0。

ZooKeeper 停机、会话过期、Provider 重启和多 Provider 重试元数据仍需要在可控 ZooKeeper 环境中执行故障演练，再记录节点收敛耗时和失败窗口。未经该演练，不应在简历中声称已经验证具体恢复时间。
